# แผนเพิ่ม Prompt Library

## ผลลัพธ์ที่ต้องการ

เพิ่มแท็บชื่อ Prompt Library ให้ผู้สร้างจาก Single-char และ Multi-char เปิดคลังเดียวกันได้ ค้นหากฎ เลือกตามสถานการณ์ ดูตัวอย่างข้อความรวม และเพิ่มลงโปรเจกต์หรือส่งออก JSON / Markdown ได้ โดยรักษาข้อความเดิมและไม่เปลี่ยนฉากหรือความสัมพันธ์อัตโนมัติ

งานรอบนี้เตรียมข้อมูลและเอกสารเท่านั้น งาน UI และการเชื่อมข้อมูลอยู่ในขั้นถัดไป

## ข้อมูลและหมวดเริ่มต้น

มี 9 รายการใน 6 หมวด: กฎพื้นฐาน ความสัมพันธ์ ระบบโบ้/การง้อ สถานการณ์และจังหวะเรื่อง หลายตัวละคร และความต่อเนื่อง/ความจำ พร้อม 3 ชุดเริ่มต้น ข้อความเป็นคำสั่งถาวรฝั่งผู้สร้าง ไม่มีตัวครอบ OOC ไม่มีระบบรันคำสั่งหรือเพิ่มความจำจริงเบื้องหลัง

## ประสบการณ์ใช้งานที่เสนอ

1. เปิดแท็บ Prompt Library โดยคง draft ปัจจุบันไว้ แสดงโหมด Single หรือ Multi ตามหน้าที่เข้ามา
2. ค้นหาจากชื่อ แท็ก คำอธิบาย และเนื้อหา กรองหมวดและโหมดได้ ค่าเริ่มต้นแสดงเฉพาะรายการที่ใช้กับโหมดนั้น
3. การ์ดแสดงชื่อ ใช้เมื่อใด และโหมดที่รองรับ เปิดอ่านเนื้อหาเต็มก่อนเลือกได้
4. เลือกทีละรายการหรือ preset แสดงรายการที่ต้องใช้ร่วมกันให้ตรวจรับ หาก dependency ไม่ครบหรือมีคู่ขัดแย้งให้แก้การเลือกก่อนเพิ่มลงโปรเจกต์ ไม่เพิ่มคำสั่งเงียบ ๆ
5. แสดงข้อความรวม จำนวนตัวอักษร และช่องปลายทาง พร้อมตัวอย่างก่อน/หลัง เรียงตามลำดับ entries ใน JSON เพื่อให้ผลคงที่
6. กด “เพิ่มกฎลงโปรเจกต์” เพื่อ append เท่านั้น หรือ “คัดลอก”, “ดาวน์โหลด .md”, “ดาวน์โหลด .json” สำหรับรายการที่เลือก
7. หลังเพิ่มแสดงผลสำเร็จและย้อนกลับได้ การดูหรือเลือกการ์ดยังไม่เปลี่ยน draft

บนมือถือใช้แท็บที่เข้าถึงด้วยคีย์บอร์ดได้และรายการการ์ดคอลัมน์เดียว พร้อมแผงตรวจข้อความที่เปิด/ปิดได้ บนเดสก์ท็อปวางรายการและตัวอย่างคู่กัน ใช้ชื่อ Prompt Library แยกจากคลังตัวละครเดิมอย่างชัดเจน

## จุดเชื่อมที่ตรวจพบในโค้ด

| ส่วน | ไฟล์ปัจจุบัน | แนวทาง |
| --- | --- | --- |
| Single workspace | `src/components/workspace/MainWorkspaceClient.tsx` | เพิ่มทางเข้า Prompt Library ทั้งเดสก์ท็อปและมือถือ ปัจจุบัน mobileTab มี editor / preview ต้องแยก state คลังออกจากการซ่อนสอง pane เดิมให้ชัด |
| Single data | `src/shared/types.ts` | เพิ่ม body ของแต่ละรายการเป็นหนึ่งสมาชิกใน `ThaiMasterCharacter.systemRules: string[]` |
| Multi workspace | `src/components/rubii-multi/RubiiMultiWorkspace.tsx` | เพิ่ม `promptLibrary` ใน TabId, TABS และส่วน render ซึ่งมีทางเข้าทั้งเดสก์ท็อปและมือถือ |
| Multi data | `src/shared/multiCharTypes.ts` | ต่อท้าย `MultiCharacterProjectDraft.castInteractionRules: string` เป็นบล็อกหัวข้อและเนื้อหา |
| Multi rule editor | `src/components/rubii-multi/CastRulesSection.tsx` | ใช้ช่องกฎเดิมเป็นปลายทางร่วม ไม่สร้างสำเนากฎที่แก้แล้วไม่ซิงค์ |
| State และ save | `src/hooks/useCharacterData.ts`, `src/hooks/useMultiCharacterProject.ts` | ใช้การอัปเดต draft และวงจรบันทึกเดิม ตรวจ signature จริงก่อนเชื่อม |

กฎที่เกี่ยวกับความสัมพันธ์ในคลังเป็นวิธีดำเนินเรื่อง ไม่ใช่ค่าความสัมพันธ์เริ่มต้น จึงไม่ใส่ทับ `initialRelationship`, `relationshipWithUser` หรือ `routes[].relationshipDynamics` โดยอัตโนมัติ รุ่นแรกไม่เปลี่ยน schema ตัวละครหรือฐานข้อมูล

## ลำดับดำเนินการ

### ระยะ 1 — ทำสัญญาข้อมูลให้พร้อมใช้

- ทบทวนเนื้อหาและความหมายของระบบโบ้จากไฟล์ร่าง
- เพิ่ม type และ validator ของคลัง: รุ่นไฟล์ ID หมวด โหมด ฟิลด์บังคับ dependency ที่ไม่มีอยู่/วนลูป และ conflict
- ย้ายหรือเชื่อม JSON เข้าส่วนข้อมูลแอปโดยมีต้นฉบับเดียว เพิ่มตัวสร้าง MD เพื่อไม่ให้สองไฟล์คลาดกัน
- สร้าง pure functions สำหรับค้นหา เลือกรายการ รวมข้อความ และส่งออก UTF-8

เกณฑ์จบ: JSON ผ่าน validation, preset ครบ dependency, ผล MD ตรง JSON และไม่แทนที่ `{{user}}`

### ระยะ 2 — สร้างหน้าคลังร่วม

- เพิ่ม shared component ที่เสนอชื่อ `src/components/prompt-library/PromptLibraryPanel.tsx`
- รองรับค้นหา กรอง เลือก ดูรายละเอียด preset และสถานะไม่พบผลลัพธ์
- ปุ่มคัดลอกและดาวน์โหลดใช้งานได้โดยไม่ต้องล็อกอินหรือเรียก AI
- JSON ส่งออกเป็น envelope รุ่น 1 พร้อม metadata หมวดที่เกี่ยวข้องและ entries ที่เลือก รวม dependency ที่ผ่านการเลือกแล้ว; ไม่แนบ presets ที่อ้างถึงรายการนอกชุดส่งออก

เกณฑ์จบ: เปิดได้จากทั้งสอง workspace ใช้งานมือถือและคีย์บอร์ดได้ คัดลอก/ดาวน์โหลดรักษาบรรทัดและภาษาไทย

### ระยะ 3 — เพิ่มกฎลง draft อย่างตรวจสอบได้

- Single: append body ลง systemRules ผ่าน updater เดิม
- Multi: append บล็อกชื่อ/เนื้อหาลง castInteractionRules ผ่าน updater เดิม
- normalize เฉพาะ line ending และ whitespace ขอบข้อความเพื่อตรวจซ้ำ ไม่แก้คำภายใน; ถ้าผู้ใช้เคยแก้ข้อความจนไม่ตรง ให้แสดงก่อน/หลังเพื่อเลือกเอง ไม่อ้างว่าตรวจความหมายซ้ำได้
- เก็บ snapshot ของช่องปลายทางก่อนเพิ่มเพื่อ Undo; หากมีการแก้ต่อแล้ว ต้องไม่คืน snapshot ทับการแก้ใหม่อย่างเงียบ ๆ
- โหมดลิงก์แชร์อ่านอย่างเดียวห้าม apply หรือแก้ draft และเคารพข้อจำกัดคัดลอก/ส่งออกของหน้าที่มีอยู่
- ตรวจว่า formatter และ checkbox ส่งออกเดิมรวมกฎที่เพิ่มจริงตามการเลือกของผู้ใช้

เกณฑ์จบ: เพิ่มแล้วบันทึก/โหลดกลับได้ ข้อความเดิมครบ เพิ่มชุดเดิมซ้ำไม่ทำให้เกิดกฎซ้ำ และ read-only ยังถูกบังคับ

### ระยะ 4 — ตรวจรับก่อนเปิดใช้

- ทดสอบ validator ด้วย ID ซ้ำ dependency หาย/วนลูป โหมดไม่ตรง และ schemaVersion ที่ไม่รองรับ
- ทดสอบการรวม/append/deduplicate และรักษาข้อความที่มีอยู่ รวมไทย บรรทัดใหม่ และ placeholder
- ทดสอบ flow จากค้นหา → เลือก → preview → apply → save/reload → export ใน Single และ Multi
- ทดสอบ empty search, clipboard ล้มเหลว, ไม่มีรายการเลือก, mobile tab และ read-only
- รัน test suite และ production build ตามสภาพแวดล้อมโปรเจกต์ก่อนส่งมอบ UI

## ขอบเขตถัดไป

รายการโปรด คลังส่วนตัว การแก้ prompt ในคลัง การนำเข้าไฟล์ และการซิงค์ cloud พิจารณาหลัง MVP ไม่จำเป็นต่อการใช้ชุดตั้งต้น การเพิ่ม OOC ฝั่งผู้เล่นในอนาคตต้องแยก audience / promptType และหน้าที่ของคำสั่งให้ชัด

ความเสี่ยงหลักคือกฎขัดกับของเดิม ความยาว prompt เพิ่ม และผลลัพธ์ต่างกันตามแพลตฟอร์ม แก้ด้วย preview การเลือกเฉพาะที่จำเป็นและทดลองกับตัวละครตัวอย่าง ไม่รับรองว่าข้อความคำสั่งเพียงอย่างเดียวจะทำให้โมเดลทำตามทุกครั้ง
