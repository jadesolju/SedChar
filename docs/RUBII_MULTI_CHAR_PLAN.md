# แผนระบบ Rubii Multi-Char Draft

สถานะ: แผนก่อนเริ่มพัฒนา  
ขอบเขต: ฟอร์มร่างโปรเจกต์หลายตัวละครสำหรับ Rubii เท่านั้น

## เป้าหมาย

เพิ่มพื้นที่ทำงานใหม่สำหรับวางโครงเรื่องที่มีตัวละครหลักหลายคน โดยเก็บข้อมูลโลกและเส้นทางเรื่องไว้ระดับโปรเจกต์ แล้วแยกข้อมูลร่างของตัวละครแต่ละคนออกจากกัน ตัวละครหลักในแผน Free เพิ่มได้ไม่เกิน 10 ตัว ส่วนตัวละครเสริมยังใช้ระบบเดิมและไม่นับรวมใน 10 ตัวนี้

ข้อมูลของตัวละครหลักเป็น **Draft Profile** ที่สั้นกว่า Single-Char ใช้จดแก่น บุคลิก พฤติกรรม ความสัมพันธ์ และข้อจำกัดสำคัญก่อน ยังไม่บังคับกรอกชีวประวัติหรือรายละเอียดเต็มทุกช่อง

## โครงหน้าที่เสนอ

1. เพิ่มปุ่ม Hamburger ที่ด้านซ้ายของแถบหัวหน้าแอป เพื่อเปิดเมนูนำทางแนวตั้ง
2. เพิ่มรายการ **Rubii Multi-Char** ในเมนูและเปิดหน้าเฉพาะ เช่น `/rubii/multi` (ชื่อ URL ยืนยันตอนลงมือทำ)
3. ในหน้า Multi-Char ใช้เมนูแท็บแนวตั้งเพื่อเปลี่ยนส่วนข้อมูล โดยเริ่มตามลำดับที่กำหนด:
   - **World Setting** — ภาพรวมโลก ฉาก ยุค สถานที่ กฎ และบรรยากาศ
   - **Lore** — ภูมิหลัง ไทม์ไลน์ เหตุการณ์ก่อนเริ่มเรื่อง ฝ่าย/กลุ่ม และความขัดแย้งหลัก
   - **Route** — เส้นทาง ความสัมพันธ์ เงื่อนไขเข้า/ออก จุดแตกแขนง และตอนจบ
   - **Main Characters** — รายการตัวละครหลัก สูงสุด 10 ตัวใน Free; เลือกหนึ่งคนเพื่อแก้ Draft Profile
4. แสดงจำนวนตัวละครหลัก เช่น `4/10` และสถานะ Draft/ความครบถ้วนของแต่ละส่วน
5. จอใหญ่แสดงแถบนำทางทางซ้ายและเนื้อหาของแท็บทางขวา; มือถือใช้ Drawer ที่เปิดจาก Hamburger และปิดหลังเลือกแท็บ

หน้าและเมนูนี้ล็อกแพลตฟอร์มเป็น Rubii ตั้งแต่ต้น ไม่แสดงตัวเลือก Purrpaw/Khui และไม่เปลี่ยนพฤติกรรมหน้า Single-Char เดิม

## ขอบเขตข้อมูล

### World Setting — ข้อมูลใช้ร่วมกันทั้งโปรเจกต์

- ชื่อโปรเจกต์, แนวเรื่องและโทน
- ยุค/ช่วงเวลา, ประเทศ/เมือง และสถานที่หลัก
- กฎของโลกหรือระบบพลังที่ทุกตัวละครต้องยึดร่วมกัน
- ฝ่าย/องค์กรสำคัญและความสัมพันธ์ระหว่างฝ่าย (เพิ่มเป็นโมดูลเสริมได้)
- สถานการณ์ตั้งต้นและความขัดแย้งหลัก

### Lore — ข้อเท็จจริงและสิ่งที่เกิดขึ้นในโลก

- ภูมิหลังโลกแบบย่อ
- ไทม์ไลน์เหตุการณ์ก่อนเริ่มเรื่อง
- เป้าหมายระยะสั้น/ระยะยาวของเรื่อง
- ความลับหรือข้อเท็จจริง พร้อมระบุว่าใครรู้/ไม่รู้
- ข้อมูลที่ทุกคนรู้ร่วมกันแยกจากข้อมูลเฉพาะตัวละคร เพื่อกันการรู้ข้อมูลข้ามตัวละครโดยไม่มีเหตุผล

### Route — เส้นทางเรื่องและความสัมพันธ์

- ชื่อ/ประเภทเส้นทาง เช่น Romance, Friendship, Rivalry, Betrayal, Neutral หรือ Route เฉพาะเรื่อง
- ตัวละครหลักที่เกี่ยวข้อง
- เงื่อนไขเริ่มต้นและเงื่อนไขปลดล็อก/เปลี่ยนเส้นทาง
- เหตุการณ์สำคัญหรือช่วงความสัมพันธ์แบบร่าง; เพิ่ม Stage 7–9 ขั้นเมื่อเรื่องต้องใช้
- จุดแตกแขนงและผลลัพธ์/Ending ที่เป็นไปได้ รวมถึงแบบไม่โรแมนติก
- กฎประจำ Route ที่อธิบายว่าพฤติกรรมหรือสถานะเปลี่ยนได้เมื่อใด

Route เป็นข้อมูลโปรเจกต์ที่เชื่อมกับตัวละครหลายคนได้ ไม่ใช่การคัดลอกข้อมูลตัวละครหนึ่งคนไปทำซ้ำทุก Route

### Main Character — Draft Profile แบบย่อ

เก็บเฉพาะข้อมูลที่จำเป็นต่อการแยกเสียงและบทบาทของตัวละครหลายคน:

- ชื่อ/ชื่อเรียก, บทบาทในเรื่อง และ Archetype หรือ Flag (ถ้าต้องการ)
- Core Concept สั้น ๆ, ภาพที่แสดงต่อคนอื่น และตัวตนจริง/ความต้องการหรือความกลัวหลัก
- เป้าหมายและความสัมพันธ์กับ `{{user}}` หรือกับตัวละครหลักคนอื่น
- กฎพฤติกรรมสำคัญในรูป `Trigger → Interpretation → Response → Limit`
- สิ่งที่ตัวละครรู้/ไม่รู้ และข้อมูลที่อนุญาตให้เปิดเผย
- สรรพนาม/น้ำเสียงสั้น ๆ และขอบเขตสำคัญ
- Route ที่เกี่ยวข้องและตัวละครเสริมที่เกี่ยวข้อง

รูปลักษณ์เชิงลึก, จิตวิทยารายการยาว, Stage ครบทุกขั้น, บทสนทนาตัวอย่าง, คำทักทาย และโมดูลเฉพาะทางเป็น Optional/ไว้เพิ่มภายหลัง ไม่ยกฟอร์ม Single-Char ทั้งชุดมาใส่ให้ตัวละครหลักทุกคน

### ตัวละครเสริม

ตัวละครเสริมยังเป็นหมวดแยกและไม่หักจากโควตา 10 ตัวละครหลัก ใช้ข้อมูล/การเลือกส่งออก/กฎตัวละครเสริมชุดเดิมก่อน ส่วนการกำหนดว่าโควตาปัจจุบันนับต่อโปรไฟล์หรือต่อโปรเจกต์ต้องยืนยันจากเพดานที่ใช้งานจริงก่อนพัฒนา: โค้ดปัจจุบันจำกัด 5 ตัวต่อ `ThaiMasterCharacter` แต่ README ระบุ 8 สำหรับ Guest และ 25 สำหรับ Member

## โครงข้อมูลสำหรับการพัฒนา

ให้สร้างชนิดข้อมูลโปรเจกต์แยกจาก `ThaiMasterCharacter` แทนการฝืนยัดหลายตัวละครลงในฟิลด์ตัวละครเสริม:

```ts
interface MultiCharacterProjectDraft {
  id: string;
  schemaVersion: 1;
  platform: 'rubii';
  title: string;
  worldSetting: WorldSettingDraft;
  lore: LoreDraft;
  routes: RouteDraft[];
  mainCharacters: MainCharacterDraft[]; // Free: สูงสุด 10
  supportingCharacters: SubCharacter[];
  status: 'draft';
  updatedAt: string;
}
```

แต่ละส่วนควรใช้ ID คงที่เพื่อเชื่อม Route ↔ Main Character ↔ Supporting Character ได้โดยไม่อาศัยลำดับ array การลบหรือเปลี่ยน ID ของตัวละครต้องอัปเดตความเชื่อมโยงและแจ้งเมื่อ Route อ้างถึงข้อมูลที่ถูกลบ

## การบันทึกและความเข้ากันได้

- ทำ Draft อัตโนมัติแยกคีย์ Local Storage จาก `sedchar_active_draft` เพื่อไม่ให้การพิมพ์ในหน้าใหม่ทับร่าง Single-Char
- สร้าง/เปิดโปรเจกต์ Multi-Char เป็นหน่วยเดียว; ห้ามบันทึก Main Character แต่ละคนเป็นระเบียนตัวละครเดี่ยวโดยอัตโนมัติ
- หากเพิ่ม Cloud Library ภายหลัง ให้ใช้ชนิดข้อมูล/ตารางโปรเจกต์แยก หรือมี versioned schema ที่ชัดเจน ไม่เปลี่ยนความหมายของ `characters.character_data` เดิมโดยเงียบ ๆ
- จำกัดการทำงานของหน้าใหม่ให้สร้าง Draft/ดูสรุป Draft สำหรับ Rubii ก่อน; การสร้าง Persona Prompt พร้อมเผยแพร่เป็นขั้นต่อไป หลังตกลงโครง export แล้ว

## แผนพัฒนาเป็นช่วง

1. **ยืนยันสเปก** — ฟิลด์ร่าง, วิธีผูก Supporting Characters, เพดานตัวละครเสริม และ Free/แผนอื่น
2. **ฐานหน้าและ Draft** — Hamburger, รายการ Rubii Multi-Char, route เฉพาะ, โครงโปรเจกต์, auto-save/restore แบบไม่แตะ Draft เดิม
3. **World Setting + Lore** — สร้างฟอร์มข้อมูลใช้ร่วมกันและตัวบ่งชี้ข้อมูลที่ตัวละครรู้/ไม่รู้
4. **Route + Main Characters** — เชื่อมเส้นทางกับตัวละคร, เพิ่ม/แก้/ลบตัวละครหลัก, บังคับเพดาน Free ที่ 10
5. **Rubii Draft Preview/Export** — สร้างสรุปที่ยังระบุว่าเป็น Draft; ค่อยตกลงรูปแบบ Persona/Moment/First Message ก่อนทำ output พร้อมคัดลอก
6. **Cloud/Entitlements (ภายหลัง)** — ซิงก์โปรเจกต์และตรวจเพดานฝั่งเซิร์ฟเวอร์เมื่อข้อกำหนด Free/แผนอื่นชัดเจน

## เกณฑ์รับงานเมื่อเริ่มพัฒนา

- ผู้ใช้เปิดหน้าใหม่จาก Hamburger ได้ และเห็น Vertical Tab Navigation ตามลำดับ World Setting → Lore → Route → Main Characters
- หน้าจอระบุชัดว่าเป็น Rubii-only และยังไม่มีการเปลี่ยน target ของ Single-Char
- Free เพิ่ม Main Character ได้สูงสุด 10; ปุ่มเพิ่มแจ้งเมื่อเต็ม และตัวละครเสริมไม่กินโควตานี้
- แต่ละตัวละครหลักเป็น Draft Profile สั้น ไม่บังคับให้กรอกข้อมูลเต็มตาม Single-Char
- Route ผูกกับ Main Character ได้หลายคน และข้อมูลความรู้/ความลับไม่รั่วข้ามตัวละครโดยอัตโนมัติ
- ปิด/เปิดหน้าแล้ว Draft Multi-Char ยังอยู่ และไม่เปลี่ยน Draft Single-Char
